## Auth rules

Use one unified auth validator for runtime MQTT and `--mqtt-save-config`.

Valid states:

- no auth
- `username + password`
- `username + password_env`

Invalid states:

- username alone
- password alone
- password_env alone
- password and password_env together

Do not silently prefer `password` over `password_env`. If both are present after CLI/config merge, return a usage error.

## Execution flow requirement

The intended flow is:

1. Parse CLI args.
2. Reject `--force-config` unless `--mqtt-save-config` is present.
3. If `--mqtt-save-config` is present:
   - validate save-config args.
   - write `wtg.toml`.
   - exit before MQTT/NVML/tracing initialization.
4. If `--mqtt-init-config` is present:
   - create the blank template.
   - exit before MQTT/NVML/tracing initialization.
5. Otherwise:
   - load/apply `--config` if supplied.
   - validate runtime args.
   - execute selected runtime mode.

Important: `--mqtt-save-config` must not skip validation.
Important: `--mqtt-save-config` should not load an existing config file. It writes from explicit CLI flags only.

## Save-config behavior

`--mqtt-save-config` should:

- write `wtg.toml` in the current directory.
- call `config::write_config_file(&SavedMqttConfig, Path::new(config::DEFAULT_CONFIG_FILE_NAME), args.force_config)`.
- refuse overwrite unless `--force-config` is supplied.
- set `[mqtt].enabled = true`.
- require `--mqtt-host`.
- require `--mqtt-node-id`.
- allow no-auth output.
- write `password` and `password_env` according to the selected auth source.
- use defaults for omitted optional values: port `1883`, topic prefix `wtg`, HA prefix `homeassistant`.
- not connect MQTT.
- not initialize NVML.
- exit after writing config.
