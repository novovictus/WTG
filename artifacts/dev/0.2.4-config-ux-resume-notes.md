## Auth rules

Use one unified auth validator for runtime MQTT and `--mqtt-save-config`.

Valid states:

- no auth
- `username + password`
- `username + password_env`

Invalid states:

- username alone
- password alone
- password_env alone
- password and password_env together

Do not silently prefer `password` over `password_env`. If both are present after CLI/config merge, return a usage error.

## Execution flow requirement

The final flow must be:

1. Parse CLI args.
2. If `--mqtt-save-config` is present:
   - validate save-config args.
   - write `wtg.toml`.
   - exit before MQTT/NVML initialization.
3. Otherwise:
   - load/apply `--config` if supplied.
   - validate runtime args.
   - execute selected runtime mode.

Important: `--mqtt-save-config` must not skip validation.
Important: `--mqtt-save-config` should not load an existing config file. It writes from explicit CLI flags only.

## Save-config behavior

`--mqtt-save-config` should:

- write `wtg.toml` in the current directory.
- call `config::write_config_file(&SavedMqttConfig, Path::new(config::DEFAULT_CONFIG_FILE_NAME), args.force_config)`.
- refuse overwrite unless `--force-config` is supplied.
- set `[mqtt].enabled = true`.
- require `--mqtt-host`.
- require `--mqtt-node-id`.
- allow no-auth output.
- write `password` and `password_env` according to the selected auth source.
- use defaults for omitted optional values: port `1883`, topic prefix `wtg`, HA prefix `homeassistant`.
- not connect MQTT.
- not initialize NVML.
- exit after writing config.

`--force-config` is valid only with `--mqtt-save-config`.

## Runtime direct-password behavior

Runtime direct password should work:

```powershell
.\wtg.exe --watch --sink mqtt `
  --mqtt-host "homeassistant-shop" `
  --mqtt-node-id "bench" `
  --mqtt-username "wtg" `
  --mqtt-password "test"
```

Config direct password should work when `[mqtt].enabled = true`:

```toml
[mqtt]
enabled = true
host = "homeassistant-shop"
port = 1883
username = "wtg"
password = "test"
password_env = ""
topic_prefix = "wtg"
node_id = "bench"
```

## Main.rs requirements

Update `apply_config()` to apply the password field:

```rust
if parsed.mqtt_password.is_none() {
    if let Some(value) = mqtt.password() {
        parsed.mqtt_password = Some(value.to_string());
    }
}
```

Update `mqtt_auth_from_args()` to resolve exactly one password source:

```rust
match (
    args.mqtt_username.as_deref(),
    args.mqtt_password.as_deref(),
    args.mqtt_password_env.as_deref(),
) {
    (Some(username), Some(password), None) => Some(MqttAuthOptions::new(username.to_string(), password.to_string()) ...),
    (Some(username), None, Some(password_env)) => Some(resolve_mqtt_auth(username, password_env, |name| env::var(name).ok()) ...),
    _ => None,
}
```

Invalid combinations should be rejected before this function is called.
