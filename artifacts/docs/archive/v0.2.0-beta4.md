# WTG v0.2.0-beta4 Release Notes

## Status

`v0.2.0-beta4` is an empirical validation beta focused on probe output, sink behavior, and experimental NVML field-value comparison under Windows WDDM.

This release remains a diagnostic beta. It is not a general output-format expansion release.

## Included

- `--probe` diagnostic output for compact telemetry snapshots.
- `--sink jsonl` for supported line-oriented output paths.
- Structured `--probe --sink csv` output.
- Experimental `--probe-fields` mode for querying explicit raw NVML field IDs through `nvmlDeviceGetFieldValues`.
- Repeatable `--field-id <u32>` arguments for `--probe-fields`.
- `wtg.version` in probe-oriented output.
- Runtime context fields for same-GPU, cross-driver comparison:
  - `driver.version`
  - `cuda.driver_version`
  - `gpu.compute_mode`
  - `gpu.pci.bus_id`
- Clarified `util.mem_controller_pct` naming to distinguish NVML memory-controller utilization from VRAM occupancy.

## Known limitations

- `--stats` does not currently integrate with sinks.
- `--probe-fields` is console-only in beta 4.
- `--once --sink csv` and `--watch --sink csv` do not emit structured CSV records.
- Structured CSV output is currently limited to `--probe`.
- Raw NVML field-value output is experimental and should not be interpreted as proof of driver causality without external validation.

## Sink support matrix

| Mode | `--sink jsonl` | `--sink csv` | Notes |
| --- | --- | --- | --- |
| `--probe` | Supported | Supported | CSV emits structured probe records. |
| `--probe-fields` | Not supported | Not supported | Experimental console-only comparison mode in beta 4. |
| `--once` | Supported as line-oriented JSONL | Not structured | CSV output is not currently implemented for this mode. |
| `--watch` | Supported as line-oriented JSONL | Not structured | CSV output is not currently implemented for this mode. |
| `--stats` | Not supported | Not supported | Stats sink integration is deferred. |

## Validation target

Validate on Windows NVML hardware before tagging:

```powershell
cargo fmt --check
cargo test
cargo build -p wtg-app --release
.\target\release\wtg.exe --once
.\target\release\wtg.exe --probe
.\target\release\wtg.exe --probe --sink jsonl
.\target\release\wtg.exe --probe --sink csv
.\target\release\wtg.exe --probe-fields --field-id 74
.\target\release\wtg.exe --probe-fields --field-id 74 --field-id 78 --field-id 83
```

## Interpretation boundary

`--probe-fields` verifies that selected NVML field-value IDs can be queried on the current device/session and reports their raw status/type/value results.

It does not infer that a specific NVIDIA driver branch caused a telemetry issue. Driver-causality claims require controlled cross-driver comparison on the same GPU with matching workload conditions.

## Deferred beyond beta 4

- Structured CSV output for `--once`.
- Structured CSV output for `--watch`.
- Sink integration for `--stats`.
- JSONL or CSV sink support for `--probe-fields`.
- Automatic interpretation of raw NVML field IDs as driver defects.
